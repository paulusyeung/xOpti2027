# POS peripherals and client matrix (legacy baseline)

Generated by `scripts/parity/build-devices.sh` into `docs/parity/devices.csv`.
Every row cites the source file it is derived from; the script fails if a cited
path is missing.

Identifiers: `DEV-001` … `DEV-009`.

## What the legacy application actually integrates

The VB6 source contains **no device-integration layer**: no `MSComm`, OPOS,
WinSock, raw printer escape sequences, line-display, drawer kick-out, signature
pad, or payment-terminal code. All output goes through Crystal Reports 6 and the
Windows print spooler; the only measured input path is the keyboard.

| ID | Device/client | Interface | Windows dependency | xOpti path |
| --- | --- | --- | --- | --- |
| `DEV-001` | Receipt/invoice printer | Windows spooler (USB/parallel/network per workstation) | VB6 + Crystal 6 (`crpe32.dll`) + printer driver | QuestPDF PDF → browser/PDF print |
| `DEV-002` | Barcode/label printer | Windows spooler + Code 39 font | Crystal 6 + `3of9.TTF` | QuestPDF barcode/label layout |
| `DEV-003` | Barcode scanner | Keyboard wedge only | focusable Win32 control | browser keyboard input |

## Findings that affect design

1. **Printing is Crystal, not ESC/POS.** Receipts, invoices, statements, claims,
   and barcode labels are all Crystal pages sent to the Windows default printer
   (`Rptlibvalid.bas:220-260`, `frmSpecialReports.frm:103`). Any ESC/POS receipt
   or network-label printing in xOpti is new work, not a port.
2. **The scanner is a keyboard.** No barcode lookup path exists in the POS; the
   operator keys the SKU. A wedge scanner works unchanged, anything else needs a
   local agent that does not exist.
3. **Cash drawer, pole display, signature pad, and payment terminal were never
   integrated.** The tender grid stores `CardNumber`/`AuthorizationCode` as typed
   text (`frmSalesOrder.frm:2835-2839`). Treat PCI exposure as an open decision,
   not as legacy behaviour to preserve.
4. **Browser support is unprecise.** The build targets ES2022
   (`web/xOpti.Web/tsconfig.json`), no `browserslist` or minimum-version policy
   exists, and only Chromium is exercised by Playwright
   (`web/xOpti.Web/playwright.config.ts`). Firefox and Safari are unverified.
5. **Label stock and printer models are undocumented.** No paper size, label
   dimension, or printer model appears in the repository; the `.rpt` page setup
   is not in the `.txt` exports.
