# Richmond report catalogue (legacy baseline)

Generated by `scripts/parity/build-report-catalogue.sh` into
`docs/parity/reports.csv`. Source: `eOptical6DAO/`, the same tree as the
production `SynergyV.mdb` snapshot.

Identifiers: `RPT-001` … `RPT-098`.

## Effective-resolution rule

`Rptlibvalid.SetRptFileName` (`Rptlibvalid.bas:228-230`) looks for
`loctext$ & "Rpt odbc\" & name & ".rpt"`, then falls back to
`loctext$ & "Rpt\" & name & ".rpt"`; `loctext$` is the application folder
(`SetSDBName`, `Rptlibvalid.bas:291-316`). A store install therefore works by
copying its overlay into the `Rpt odbc` folder. Because all five tiers are
present in this repository, the catalogue applies the precedence required by
the change to the logical name (case-insensitive file stem):

```
Rpt ODBC/Richmond/HST > Rpt ODBC/Richmond > Rpt ODBC > Rpt DAO > Rpt
```

Only the winning copy is catalogued; lower-precedence copies are counted in
`notes`. Matching is by file name because that is the only key
`SetRptFileName` uses.

All 98 have a sibling Crystal definition export (`.txt`); 97 supply their data
dependencies from it. `RPT-060` (`Prescription`) ships only an 82-line stub

`data_tables_source = binary-fallback`; the joins must be confirmed with the

`Rpt DAO` contributes no effective report: all nine of its files are superseded
by same-named copies in `Rpt ODBC`. `Rpt ODBC/Richmond/Address.txt` is an
orphan definition with no `.rpt` and is not catalogued. The per-store overlay
folders (`OpticalRbs/`, `OpticalRmd/`, `OpticalPacific/`) are other customers'
installs and are outside the Richmond precedence chain.

## Parameters

Crystal v6 text exports omit the parameter-field definitions, so parameters are
recovered from `{@Ask*}` formula references and `{?…}` query links, and their
types are inferred from the name (`AskDateFrom` → date, `AskNoCost` → boolean,
`AskPctAbove` → percent, …). The CSV lists each parameter as `name:type`;
treat the type as a prompt for 3.4, not as a verified control type.

- 67 of 98 reports prompt for at least one parameter; 31 take none.
- 19 distinct prompts, dominated by `AskDateFrom`/`AskDateTo` (87 references),
  then `AskDept`/`AskClass`/`AskCat` (54 each) and
  `AskTxNumberFrom`/`AskTxNumberTo` (45/27).
- `RPT-*` files with the automatic `{?Pm-TxPayment.TxNumber}` link parameter are
  flagged as `query-link`.

## Data dependencies

50 distinct legacy tables appear across the catalogue; the most common are
`TxHeader` (53 reports), `Brand` (51), `TxDetails` (44), `Staff` (41),
`Inventory` (37), `PaymentMethods` (35). The full per-report list is in
`data_tables`.

Reports that read `TxHeader`/`TxDetails`/`TxPayment` are financial-parity
critical because their totals must reconcile to migrated data.

## Criticality (proposed, awaiting 3.4)

`criticality` is a triage default with its rule recorded in
`criticality_basis`:

| Criticality | Count | Rule |
| --- | ---: | --- |
| `high` | 58 | name matches financial/legal vocabulary, or reads transaction tables |
| `medium` | 15 | inventory/stock/wholesale/order operations |
| `low` | 25 | master-data listing or lookup |

`in_scope` and `signoff_status` are `pending` for every row. Task 3.4 records the
customer decision; task 3.3 does not guess it.
